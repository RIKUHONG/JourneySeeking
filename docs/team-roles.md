# 团队工作面与协作

P0 与 P1 的历史分工不延续为 P2 指派。P2 所有 Issue 的负责人均待定；具体任务、依赖和验收见 [P2 Issue 草案](p2-issues.md)。此处只规定工作边界，认领时由团队确认个人、评审人和排期。

| 工作面 | 主要 Issue | 主要目录/契约 | 与其他工作面的交接 |
| --- | --- | --- | --- |
| API/模型 | P2-01 | `docs/api-contract.md`、`backend/app/models/`、`backend/app/main.py` | 冻结 ID、版本、错误码和 OpenAPI；其他工作面按契约实现 |
| 地图/候选 | P2-02 | `backend/app/services/poi_candidates.py`、地图集成及测试 | 向编排提供可信候选和城市覆盖状态 |
| 数据/RAG | P2-03 | 新增知识数据、检索服务、评估集 | 向编排提供带来源/版本的片段 |
| 持久化/会话 | P2-04、P2-06 | 新增存储和会话服务 | 向编辑、前端、导出提供行程版本与会话状态 |
| 编辑/编排 | P2-05、P2-07 | 行程 service、Agent/工具边界 | 编辑只改指定范围；编排只消费可信来源数据 |
| 前端/导出 | P2-08、P2-09 | `frontend/`、导出 service | 前端先用契约 mock，导出读取已保存版本 |
| 质量集成 | P2-10 | `backend/tests/`、前端测试、CI、文档 | 按每个工作面持续补验证，最终做端到端验收 |

同一工作面可由多人认领，但一个 Issue 只保留一个集成责任人；评审人由其他工作面承担。修改共享模型或 `TripService` 前先在 P2-01 中确认字段和版本语义。每个 PR 关联 Issue，说明验证命令、契约/配置/迁移影响，至少一名非作者评审；不直接向 `main` 推送。
