# P2-05 单日局部编辑

## 接口

`POST /api/trip/{trip_id}/edit` 接收当前 `expected_version`、目标 `date` 和自然语言
`instruction`。服务端始终从存储读取当前版本，不接受客户端提交的完整行程。成功响应包含
递增后的版本、完整行程和 `change_summary`。

## 编辑边界

MoMA 只允许返回目标日的 `date`、`title` 和 `activities`。草稿包含目的地、日期范围、
天气、路线、总费用或其他额外字段时直接拒绝。服务端将草稿合并到当前行程的深拷贝中，
并逐字段保持非目标日、目的地、日期范围、摘要和行程身份不变。

新增 POI 必须来自本次城市候选池。地图候选不可用时，只允许继续使用当前版本中已经核实
的 POI，或修改目标日原有的未核实活动，不接受模型创造的新地点。候选数据由服务端写回
坐标和来源；模型不能提交坐标、路线或地图核实状态。目标日的旧路线事实不会跨编辑复用。

目标日费用变化按活动费用差额更新总费用。合并结果还会检查 POI 唯一性，并通过规则
Critic 校验日期顺序、费用、POI 来源、路线和天气事实。任一检查失败都不会写入版本。

## 并发与失败

服务在调用模型前快速检查 `expected_version`，最终保存仍使用 SQLite 的条件更新，因此并发
请求中只有一个旧版本写入能够成功。不存在的行程返回 `404`，版本冲突返回 `409`，无效
日期或草稿返回 `422`，MoMA 超时返回 `504`。最终保存之前不会创建中间版本。

当前存储契约没有单独保存最初的 travelers、budget、preferences 等请求字段。本实现严格冻结
已持久化行程能够表达的硬约束；后续若需跨轮持续校验原始请求约束，应由会话或存储模型显式
持久化这些字段后再传入编辑 Critic。
