# P2 差距清单与 Issue 分工

核对基线：2026-09-29 的本地 `main`（`6f76009`，已合并生成链路修复）；参考项目为根目录下本地 `helloagents-trip-planner/`。参考项目只用于识别能力差距，接口、模型和实现以本仓库为准；该目录不提交到本仓库。`python -m pytest -q` 在基线上为 142 passed。真实杭州生成链路样例见 `docs/fixtures/trip-generate-hangzhou-20260929.json`，它不是持续的线上联调测试。

## 已有能力与差距

| 能力 | 当前 `main` | 参考项目可核对位置 | P2 处理 |
| --- | --- | --- | --- |
| 结构化生成 | `POST /api/trip/generate`、MoMA 解析/校验、3～7 天请求 | `backend/app/api/routes/trip.py` | 保留现有契约，补端到端失败场景 |
| POI、路线、天气 | 候选 POI ID 校验、地图补全、内存地图缓存、逐日天气与雨天提示 | `services/place_candidate_service.py`、`map_service.py`、`weather_service.py` | P2-02 完善城市解析和候选不足判定；天气自动调度另列候选 |
| 城市攻略检索 | 无本地知识库、检索或评估集 | `backend/app/rag/`、`backend/data/` | P2-03 |
| 保存与历史 | 无行程 ID、数据库或增删查接口 | `services/storage_service.py`、`api/routes/trip.py` | P2-01、P2-04 |
| 局部修改与多轮 | `/api/chat` 只是原始 MoMA 消息转发；无行程编辑或服务端会话 | `api/routes/trip.py`、`agents/trip_planner_agent.py` | P2-05、P2-06；参考项目的单次编辑也不等于完整多轮状态 |
| 编排与可解释校验 | 固定生成→地图→天气链路，无 Agent 状态或执行轨迹 | `agents/`、`services/trip_service.py` | P2-07 |
| 前端与导出 | 无 `frontend/`，无 Markdown/PDF 接口 | `frontend/src/`、`api/routes/export.py` | P2-08、P2-09 |
| Redis | 有 `Cache` 协议和进程内 `MemoryCache`，无 Redis adapter | `services/cache_service.py` | 条件任务 P2-C1；不能成为启动依赖 |

参考项目有 SQLite、Redis、六城攻略和可运行前端，但其 README 的功能声明不是本项目验收证据。当前项目已有一次真实生成链路样例；默认测试仍不连接外部服务。

## 分工与推进

每个编号是一个独立 Issue/PR 的交付边界。A 负责 API/模型与持久化；B 负责 RAG、编辑、编排和集成验收；C 负责地图候选、会话、前端和导出。各负责人按下表依赖顺序从合并后的最新 `main` 创建对应分支，不把多个 Issue 混入同一 PR。跨工作面字段先由 P2-01 定义，至少由受影响工作面的另一位成员评审。

### P2-01 契约与行程身份

**负责人：A；分支：`feature/p2-api-contract`。**

- 范围：在 `docs/api-contract.md`、`backend/app/models/` 定义稳定 `trip_id`、`version`、编辑/保存/历史/导出接口与错误码；明确旧 `generate` 响应的兼容方式，并统一未预期 500 与 `/api/chat` 的错误边界。记录天气、地图、RAG 来源字段的可选性。
- 具体内容：列出请求/响应示例、ID 生成时点、初始版本号、更新冲突码、404/422/500 结构与可选字段序列化；更新 Pydantic 模型、OpenAPI 和契约测试。邀请 B/C 在字段冻结前评审编辑、候选和 RAG 输入。
- 不包含：数据库、编辑算法、前端。契约 PR 只改契约、模型和契约测试。
- 验收：OpenAPI 与示例一致；旧请求及响应必填字段兼容；ID 不由模型生成；同一行程版本冲突有确定 HTTP 状态；500 与聊天供应商异常不泄露密钥、Prompt 或内部路径。

### P2-02 城市解析与候选门槛

**负责人：C；分支：`feature/p2-city-candidates`。**

- 范围：在地图/候选服务中确认单城市、别名、行政区和省级输入；按景点/餐饮/住宿分类检查候选数量、城市归属和坐标；候选不足给出确定的降级或错误状态。
- 具体内容：建立城市解析结果与覆盖状态；在 `poi_candidates.py` 采集后去重、过滤跨城/无坐标候选，配置分类最小数；向 B 的编排传可信候选池与不足原因，错误响应遵循 P2-01。
- 不包含：RAG、Prompt 结构重写、数据库。与 P2-07 的接口只传可信候选和覆盖状态。
- 验收：别名、跨城 POI、不足候选、供应商失败、省级输入均有离线测试；每类不足数和拒绝原因可检查；模型输出仍只能引用当次候选 ID；无伪造 POI。

### P2-03 攻略知识库与检索

**负责人：B；分支：`feature/p2-rag-retrieval`。**

- 范围：建立可审阅的城市攻略数据、切分/目的地 metadata、检索接口和离线评估集；先实现确定性关键词检索，再依据评估结果决定是否接入向量库/Rerank。
- 具体内容：确定首批城市与合法知识来源，编写导入/切分和元数据校验；提供按城市和查询词检索的 service 接口、空结果降级与 Top-K 评估脚本；把片段来源及版本交给 P2-07。
- 不包含：修改生成 API、自动导入参考项目文本或强制引入 Chroma。检索结果包含来源和版本，供 P2-07 使用。
- 验收：离线评估集和运行命令入库；测试覆盖跨城市隔离、空命中、重复和过期资料；记录 Top-K 命中率及跨城污染率基线；知识库不可用时生成链路有明确降级。

### P2-04 保存、历史与版本

**负责人：A；分支：`feature/p2-trip-storage`。**

- 范围：基于 P2-01 实现行程保存、列表、详情、删除和版本递增；采用仓库当前部署规模可支持的持久化方案并记录迁移路径。保存完整当前契约的 `Itinerary`，不得直接套用参考模型。
- 具体内容：实现存储模型/迁移、仓储接口和 HTTP 路由；版本更新使用预期版本条件写入；提供分页或有界列表，避免历史记录无限返回。向 B/C 暴露按 ID/版本读取与原子更新服务。
- 不包含：自然语言编辑、导出渲染。接口提供 P2-05/06/09 可复用的存取服务。
- 验收：重启后可读；不存在返回 404；相同旧版本的第二次写入被拒绝且未覆盖新版本；列表顺序和上限稳定；删除后无法读取；测试使用隔离数据库且无外部账号依赖。

### P2-05 单日局部编辑

**负责人：B；分支：`feature/p2-trip-edit`。**

- 范围：按 P2-01 确定的编辑路径实现单日修改（建议 `POST /api/trip/{trip_id}/edit`），明确 `date` 和自然语言指令；只更新指定日期，保持目的地、日期、其他天及用户硬约束。重新校验费用、POI/路线和天气受影响部分，写入新版本。
- 具体内容：构造限定日期的编辑 Prompt 与结构化草稿；在 service 层比较修改前后差异，拒绝范围外修改；复用 P2-04 原子版本写入，并仅重算受影响的费用与补全字段。
- 不包含：跨会话记忆、批量重排。生成草稿与校验分开，拒绝越界 POI 和无效日期。
- 验收：未指定日逐字段不变；编辑失败不覆盖原版本；版本冲突、模型超时、无效日期、越界 POI 和错误费用均有测试；返回修改摘要与可追溯版本。

### P2-06 多轮上下文

**负责人：C；分支：`feature/p2-session-context`。**

- 范围：基于已保存行程管理会话 ID、近期指令摘要、不可变硬约束及版本引用；后续编辑从服务端当前版本读取状态，支持会话删除和过期策略。
- 具体内容：定义会话记录和 TTL、指令窗口与摘要上限；将会话中的行程 ID/版本传给 B 的编辑服务，成功后原子更新会话版本；拒绝跨行程或过期会话，不复制 `/api/chat` 的无状态消息列表。
- 不包含：长期用户画像或直接依赖 MoMA 平台私有上下文 API。`/api/chat` 不冒充行程会话接口。
- 验收：至少两轮局部编辑保持预算/日期等硬约束；旧版本、跨行程和过期会话被拒绝；上下文长度有上限；删除后不可恢复会话状态。

### P2-07 编排与 Critic 校验

**负责人：B；分支：`feature/p2-agent-orchestration`。**

- 范围：在 service 层定义有限步数的状态与工具调用记录，接入可信候选、RAG、MoMA、地图和天气；以规则 Critic 检查日期、预算、POI 来源、路线可执行性。先实现可测试的编排，再评估是否需要 LangGraph。
- 具体内容：定义输入/输出 Schema、步骤状态和工具超时；按城市覆盖结果选择检索或候选路径；接入现有 `TripService` 生成/补全，输出可脱敏执行轨迹与 Critic 报告。
- 不包含：为每个工具创建独立 LLM Agent、改造供应商适配器。工具失败应有可解释的降级和有限重试。
- 验收：离线轨迹说明调用顺序、来源、耗时和失败原因；最大步骤数和超时有效；Critic 拒绝日期、预算或 POI 来源违规，不能把未知来源标记为已核实；P0/P1 契约回归通过。

### P2-08 前端生成与管理

**负责人：C；分支：`feature/p2-frontend-workflow`。**

- 范围：建立 Vue 3/TypeScript 前端；覆盖请求表单、生成中/失败状态、每日活动/地图/天气、局部编辑、保存、历史和导出入口。先用 P2-01 契约 mock，后接真实 API。
- 具体内容：建立 API client 与类型、生成和结果视图、地图/天气状态、单日编辑、历史列表/详情、保存/删除和导出操作；对 404、版本冲突、部分补全及重试提供明确交互。
- 不包含：复制参考项目前端样式或私有类型；前端不重新推断天气/POI 真伪。
- 验收：桌面和手机可完成生成→编辑→保存→重开→导出流程；无数据、加载、部分天气、服务失败和版本冲突均可辨识；类型检查、构建和关键交互测试通过。

### P2-09 Markdown/PDF 导出

**负责人：C；分支：`feature/p2-trip-export`。**

- 范围：从 P2-04 中保存的行程版本生成 Markdown 和 PDF；展示日期、活动、来源及未知天气，处理中文字体和下载文件名。
- 具体内容：实现纯渲染 service 与下载路由；输入固定为存储的行程版本，输出包含可信来源提示及预算信息；封装中文字体，避免本机路径进入响应。
- 不包含：重新生成或修改行程。导出内容按存储版本固定。
- 验收：404、中文、空活动、长文本和多页 PDF 有测试；同一版本重复导出内容一致；内容不包含 Prompt、Key 或内部日志；下载媒体类型与文件名正确。

### P2-10 集成验收与观测

**负责人：B；分支：`feature/p2-e2e-observability`。**

- 范围：维护生成/编辑/保存/导出的离线端到端场景、真实服务手工检查清单、请求 ID 与步骤耗时/失败类别；建立质量、延迟与 token/成本基线。
- 具体内容：串联 A/B 的功能测试和前端流程，维护无密钥 CI、故障注入与验收记录；采集阶段耗时、POI/路线核实率和外部服务失败类别，文档化真实 Key 的手工联调步骤。
- 不包含：把生产密钥加入 CI，或以演示脚本替代自动测试。
- 验收：无密钥 CI 可运行；外部服务故障时基础行程和已存数据仍可用；请求 ID 能串联各步骤且日志不泄密；README 给出部署/回滚检查；P2 核心流程有一次可复现验收记录。各功能 Issue 的单元测试仍由各自负责人完成。

## 条件任务，不阻塞 P2 核心验收

### P2-C1 Redis adapter

**负责人：C；分支：`feature/p2-redis-cache`。**

- 启动条件：多实例部署、缓存命中率或供应商限流数据表明进程内缓存不足；先在 Issue 记录具体数据和目标。
- 工作范围与内容：实现现有 `Cache` 协议的 Redis adapter、配置、序列化和 TTL；在依赖注入处选择 Redis 或内存实现。缓存只存可重建数据，不存唯一行程或会话事实。
- 验收：命中、过期、序列化、断连和重连测试通过；Redis 关闭时应用仍可启动并降级到内存或无缓存；无 Redis 的默认 CI 继续通过。A 评审配置与部署影响。

### P2-C2 天气触发自动调度

**负责人：B；分支：`feature/p2-weather-rescheduling`。**

- 启动条件：P2-05/06/07 完成，并已有天气来源、候选替代活动和用户确认契约；C 评审天气证据。
- 工作范围与内容：只对受影响日期生成候选替换与路线差异，先返回预览、原因和新旧版本；用户确认后才调用版本写入。未知天气不触发自动修改。
- 验收：拒绝确认、重复确认、天气失效、候选不足和版本冲突均不覆盖原行程；确认后仅修改授权日期，费用/路线重新校验；离线场景测试通过。

P2 核心验收以 P2-01～10 为范围；条件任务在满足启动条件时单独建 Issue/PR。负责人已指定，启动时间与技术选型在对应 Issue 中确认，不改变这里的契约和交付边界。
