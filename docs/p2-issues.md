## 分工与推进

每个编号是一个独立 Issue/PR 的最小交付边界。负责人均为 **待定**；下表的“工作面”用于避免多人同时改同一核心文件，不预设成员 A/B/C。跨工作面变更先由 P2-01 定义契约并在 PR 中标记共同评审。每个 Issue 从当时最新 `main` 建分支，分支建议 `feature/p2-<主题>`。

| --- | --- | --- | --- |

### P2-01 契约与行程身份

- 范围：在 `docs/api-contract.md`、`backend/app/models/` 定义稳定 `trip_id`、`version`、编辑/保存/历史/导出接口与错误码；明确旧 `generate` 响应的兼容方式，并统一未预期 500 与 `/api/chat` 的错误边界。记录天气、地图、RAG 来源字段的可选性。
- 不包含：数据库、编辑算法、前端。契约 PR 只改契约、模型和契约测试。
- 验收：OpenAPI 与文档一致；旧请求仍可解析；ID 不由模型生成；同一行程版本语义明确，冲突有确定 HTTP 状态；无密钥或用户数据泄露。

### P2-02 城市解析与候选门槛

- 范围：在地图/候选服务中确认单城市、别名、行政区和省级输入；按景点/餐饮/住宿分类检查候选数量、城市归属和坐标；候选不足给出确定的降级或错误状态。
- 不包含：RAG、Prompt 结构重写、数据库。与 P2-07 的接口只传可信候选和覆盖状态。
- 验收：跨城 POI、不足候选、供应商失败、省级输入均有离线测试；模型输出仍只能引用当次候选 ID；无伪造 POI。

### P2-03 攻略知识库与检索

- 范围：建立可审阅的城市攻略数据、切分/目的地 metadata、检索接口和离线评估集；先实现确定性关键词检索，再依据评估结果决定是否接入向量库/Rerank。
- 不包含：修改生成 API、自动导入参考项目文本或强制引入 Chroma。检索结果包含来源和版本，供 P2-07 使用。
- 验收：测试覆盖跨城市隔离、空命中和过期资料；有 Top-K 命中率及污染率基线；知识库不可用时生成链路有明确降级。

### P2-04 保存、历史与版本

- 范围：基于 P2-01 实现行程保存、列表、详情、删除和版本递增；采用仓库当前部署规模可支持的持久化方案并记录迁移路径。保存完整当前契约的 `Itinerary`，不得直接套用参考模型。
- 不包含：自然语言编辑、导出渲染。接口提供 P2-05/06/09 可复用的存取服务。
- 验收：重启后可读；不存在返回 404；并发旧版本写入有冲突响应；删除后无法读取；测试使用隔离数据库且无外部账号依赖。

### P2-05 单日局部编辑

- 范围：按 P2-01 确定的编辑路径实现单日修改（建议 `POST /api/trip/{trip_id}/edit`），明确 `date` 和自然语言指令；只更新指定日期，保持目的地、日期、其他天及用户硬约束。重新校验费用、POI/路线和天气受影响部分，写入新版本。
- 不包含：跨会话记忆、批量重排。生成草稿与校验分开，拒绝越界 POI 和无效日期。
- 验收：未指定日不变；编辑失败不覆盖原版本；版本冲突、模型超时、无效结果有测试；返回修改摘要与可追溯版本。

### P2-06 多轮上下文

- 范围：基于已保存行程管理会话 ID、近期指令摘要、不可变硬约束及版本引用；后续编辑从服务端当前版本读取状态，支持会话删除和过期策略。
- 不包含：长期用户画像或直接依赖 MoMA 平台私有上下文 API。`/api/chat` 不冒充行程会话接口。
- 验收：至少两轮局部编辑可保持预算/日期等硬约束；旧版本与跨会话混用被拒绝；上下文长度有上限；删除后不可恢复会话状态。

### P2-07 编排与 Critic 校验

- 范围：在 service 层定义有限步数的状态与工具调用记录，接入可信候选、RAG、MoMA、地图和天气；以规则 Critic 检查日期、预算、POI 来源、路线可执行性。先实现可测试的编排，再评估是否需要 LangGraph。
- 不包含：为每个工具创建独立 LLM Agent、改造供应商适配器。工具失败应有可解释的降级和有限重试。
- 验收：离线轨迹可说明调用顺序、来源、失败原因；最大步骤数和超时有效；Critic 不能将未知来源标记为已核实；P0/P1 契约回归通过。

### P2-08 前端生成与管理

- 范围：建立 Vue 3/TypeScript 前端；覆盖请求表单、生成中/失败状态、每日活动/地图/天气、局部编辑、保存、历史和导出入口。先用 P2-01 契约 mock，后接真实 API。
- 不包含：复制参考项目前端样式或私有类型；前端不重新推断天气/POI 真伪。
- 验收：桌面和手机可完成生成→编辑→保存→重开→导出流程；无数据、加载、部分天气、服务失败均可辨识；类型检查和关键交互测试通过。

### P2-09 Markdown/PDF 导出

- 范围：从 P2-04 中保存的行程版本生成 Markdown 和 PDF；展示日期、活动、来源及未知天气，处理中文字体和下载文件名。
- 不包含：重新生成或修改行程。导出内容按存储版本固定。
- 验收：404、中文、空活动、长文本和多页 PDF 有测试；内容不包含 Prompt、Key 或内部日志；下载媒体类型与文件名正确。

### P2-10 集成验收与观测

- 范围：维护生成/编辑/保存/导出的离线端到端场景、真实服务手工检查清单、请求 ID 与步骤耗时/失败类别；建立质量、延迟与 token/成本基线。
- 不包含：把生产密钥加入 CI，或以演示脚本替代自动测试。
- 验收：无密钥 CI 可运行；外部服务故障时基础行程和已存数据仍可用；README 给出部署/回滚检查；P2 核心流程有一次可复现验收记录。

## 条件任务，不阻塞 P2 核心验收

- **P2-C1 Redis adapter**：只有在多实例部署、缓存命中率或供应商限流数据表明进程内缓存不足时启动。替换 `Cache` 实现并测试断连降级；保留内存模式，Redis 不成为启动硬依赖。
- **P2-C2 天气触发自动调度**：先定义用户确认与差异预览，再做候选活动替换和局部重排；需要 P2-05/06/07 与有来源的天气数据。未知天气不得触发自动修改，未经确认不覆盖原版本。

P2 核心验收以 P2-01～10 为范围；条件任务单独评审并单独建 Issue。负责人、工期和技术选型在各 Issue 认领时确定，不改变这里的契约和交付边界。
